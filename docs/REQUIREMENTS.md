# FileCheck V0.1 需求说明

## 1. 产品目标

FileCheck 用于 Windows 终端文件自查。第一阶段重点解决三个问题：

1. 快速找出文件名/路径命中关键字符的文件；
2. 对候选文件进行人工复核并决定是否迁移或打包备份；
3. 保留完整原始路径和校验信息，以便在适当时机恢复到原位置。

## 2. 检索要求

### 2.1 Everything 优先

目标环境已安装 Everything 1.4。FileCheck 应优先通过 ES CLI 调用 Everything 索引进行文件检索。

启动时执行能力检测：

- 是否运行在 Windows；
- `es.exe` 是否存在；
- Everything IPC 是否可用；
- 查询是否可正常返回结果。

查找顺序：

1. 程序配置中的 `es.exe` 路径；
2. FileCheck 自身 `tools/` 目录；
3. 系统 PATH；
4. 常见 Everything 安装目录；
5. 全部失败后切换原生扫描引擎。

### 2.2 关键词扫描

关键词由配置文件维护，支持分组，例如：

- 高优先级词；
- 重点复核词；
- 一般复核词。

命中关键词仅表示“候选文件”，不自动判断文件性质。

### 2.3 文件类型过滤

V0.1 默认重点关注：

`.doc .docx .xls .xlsx .ppt .pptx .pdf .txt .wps .zip .rar .7z .dwg`

允许用户增加或减少扩展名。

### 2.4 扫描范围

支持：

- 全部本地固定磁盘；
- 指定盘符；
- 指定目录；
- 排除指定目录。

默认排除 FileCheck 自身运行数据和备份目标目录，避免重复扫描。

## 3. 候选文件处理

扫描结果至少显示：

- 是否选择；
- 文件名；
- 完整路径；
- 命中关键词；
- 文件大小；
- 修改时间；
- 风险分组；
- 所在目录；
- 当前处理状态。

用户可以：

- 标记“保留”；
- 标记“待复核”；
- 选择迁移；
- 选择打包备份；
- 按目录批量处理。

## 4. 目录级判断

当一个目录中存在多个需要处理的候选文件时，FileCheck 应支持记录整个目录结构，而不是只记录单个文件。

目录处理建议规则：

- 单文件命中：默认记录单文件原路径；
- 同目录多个文件命中：提示是否按目录整体备份；
- 用户明确选择整个目录：记录目录根路径及内部相对路径；
- 不自动扩大范围，目录整体处理必须由用户确认。

## 5. 迁移与备份

支持两种模式。

### 5.1 目录迁移模式

将选中文件复制到目标根目录，并保留其相对目录结构。

示例：

源：`D:\work\projectA\design.docx`

目标根：`X:\FileCheckBackup\20260907_120000\`

备份后：`X:\FileCheckBackup\20260907_120000\files\D\work\projectA\design.docx`

### 5.2 打包备份模式

将选中文件打包为一个备份包，备份包必须同时包含 manifest。

V0.1 优先支持 ZIP；后续可增加 7z。

## 6. 完整性校验

每个迁移文件至少记录：

- 原始绝对路径；
- 备份包/目标中的相对路径；
- 文件大小；
- 原文件 SHA-256；
- 备份后 SHA-256；
- 原修改时间；
- 执行时间；
- 处理动作；
- 关键词命中原因。

仅当源和目标 SHA-256 一致时，状态才允许标记为 `verified`。

## 7. Manifest

每次备份生成唯一批次 ID，并保存 manifest。

建议结构：

```json
{
  "schema_version": 1,
  "batch_id": "20260907_120000_xxxxxx",
  "created_at": "2026-09-07T12:00:00+08:00",
  "mode": "directory_copy",
  "files": [
    {
      "source_path": "D:\\work\\projectA\\design.docx",
      "backup_path": "files\\D\\work\\projectA\\design.docx",
      "size": 12345,
      "sha256": "...",
      "mtime_ns": 0,
      "matched_keywords": ["..."],
      "status": "verified"
    }
  ]
}
```

## 8. 恢复

用户选择一个历史备份批次后，FileCheck 根据 manifest：

1. 检查备份文件是否存在；
2. 重新计算 SHA-256；
3. 显示原始路径；
4. 检查原路径当前是否已经存在同名文件；
5. 若存在，必须人工选择：跳过 / 改名恢复 / 覆盖；
6. 创建缺失目录；
7. 恢复文件；
8. 恢复后再次校验 SHA-256；
9. 记录恢复结果。

默认禁止无提示覆盖。

## 9. 数据与安全要求

- 默认离线运行；
- 不上传扫描结果；
- 不记录文件正文到日志；
- 日志不得包含不必要的内容片段；
- 扫描结果和 manifest 默认保存在本机运行数据目录；
- Git 仓库 `.gitignore` 必须忽略运行数据、报告、数据库、manifest、备份目录；
- 不提供清理 Recent、浏览器历史、USB 历史、注册表 MRU 等“清痕”功能。

## 10. V0.1 验收标准

- Everything 1.4 环境下可以快速返回关键词命中文件；
- Everything 不可用时有明确错误提示并可切换原生扫描；
- 支持关键词和扩展名配置；
- 支持按文件和目录选择；
- 支持复制备份和 ZIP 打包；
- 所有备份文件均经过 SHA-256 校验；
- 可依据 manifest 恢复到原路径；
- 对路径冲突有安全处理；
- 扫描和备份运行数据不会被 Git 跟踪。
