# FileCheck v0.2.1

FileCheck v0.2.1 是针对 v0.2.0 的 Windows 深层目录兼容性修复版本，建议所有使用 GUI 或 CLI 执行备份/恢复的用户升级。

## 修复：Windows 7 深层目录备份可能报 `[Errno 2]`

v0.2.0 为了保留原始盘符和目录结构，会将源路径镜像到：

```text
<备份根目录>\.<批次>.incomplete\files\<盘符>\<原目录树>\<文件名>
```

这会在原路径基础上额外叠加备份根目录、批次目录和 `files\<盘符>`。如果源目录本身已经很深，即使原文件在 Windows 中可以正常访问，镜像后的备份路径也可能接近或超过传统 Windows `MAX_PATH`。

此外，v0.2.0 的原子复制临时文件还会再次重复完整原文件名并附加 32 位 UUID，例如：

```text
.新建文本文档.txt.65738f732c5e459ebdb471a472b7c935.part
```

因此存在两层路径膨胀：

1. 原始目录树 + 备份目录前缀；
2. 临时文件再次重复原文件名。

在 Windows 7 上可能最终表现为：

```text
[Errno 2] No such file or directory
```

## v0.2.1 的解决方式

### 1. 普通路径继续保持原目录结构

只要镜像后的正式路径和原子临时路径都处于保守安全范围内，仍按原有方式保存：

```text
files\E\01-task\...\新建文本文档.txt
```

因此绝大多数备份仍然可以直接按原目录结构浏览。

### 2. 深层目录自动切换为紧凑存储

当镜像路径可能触碰 Windows 7 的路径长度边界时，不再强行继续叠加原目录层级，而是只对该文件自动使用固定长度的紧凑路径，例如：

```text
files\_long\E\ab\<源路径SHA-256>.docx
```

完整原始路径仍保存在 `manifest.json` 的 `source_path` 中，实际存储路径记录在 `backup_path` 中，因此验证、源文件删除和恢复都不依赖物理目录必须与原路径完全一致。

一个备份批次可以同时包含普通镜像文件和紧凑存储文件，不需要用户选择模式。

### 3. 原子临时文件改为固定短名称

备份和恢复临时文件统一改为固定长度短名称，例如：

```text
.fc-b-65738f732c5e459e.part
.fc-r-0123456789abcdef.part
```

临时文件仍位于最终目标同一目录，因此原子替换、SHA-256 校验和异常清理语义不变。

针对本次实际报告案例，镜像后的正式备份文件路径为 221 字符；v0.2.0 的旧临时路径正好达到 260 字符；v0.2.1 的短临时路径缩短为 238 字符，因此该案例仍可以保留完整镜像目录结构。对于比该案例更深的目录，程序会自动切换到 `files\_long\...`，避免正式备份路径本身继续超过安全范围。

## 兼容性

- `manifest.json` 仍使用 schema version 1；
- 新批次的 `storage_layout` 标识为 `mirrored-source-tree-with-compact-fallback-v2`；
- 每个文件可选记录 `storage_path_mode` 为 `mirrored` 或 `compact-long-path`；
- v0.2.0 已有的 `mirrored-source-tree-v1` 备份继续可以验证和恢复，不需要迁移；
- Everything 专用数据库、扫描结果和删除状态格式不变。

## 回归测试

本版本新增专门的路径回归测试：

- 使用实际报错路径验证旧临时路径为 260 字符、新路径为 238 字符；
- 验证该实际案例仍选择普通镜像存储；
- 构造更深的路径，验证自动切换到 `files/_long/`；
- 验证紧凑路径固定、可区分不同源路径并保持常见扩展名；
- 验证紧凑存储仍可完成完整备份 → SHA-256 验证 → 删除源文件 → 按原路径恢复；
- 验证 v0.2.0 风格 manifest 仍可正常验证和恢复；
- 验证备份/恢复原子临时文件使用短名称并正确清理；
- 新增版本一致性测试，确保 `pyproject.toml` 与运行时 `filecheck.__version__` 一致。

正式发布仍通过 Python 3.8.10 Win7 兼容构建链，并重新执行完整回归、GUI/CLI 打包、EXE smoke test、ZIP 内容验证和 SHA-256 生成。
